1. 用户希望以现代 Python 工程方式开发，借助 AI 协作逐步完善项目，不一次性堆砌框架。
2. 文档偏好：简洁、直接写怎么做，使用 `1. 2. 3.` 编号，避免长篇背景和解释。

4. 业务事实以[需求文档](../../docs/requirements.md)为准，技术选择以[决策记录](decisions.md)为准，临时进度以[交接记录](handoff.md)为准。
5. 仅记录用户明确表达的稳定目标与偏好，不保存推测、敏感数据或可从代码和 Git 历史直接获取的内容。
