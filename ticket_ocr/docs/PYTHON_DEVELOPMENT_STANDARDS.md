# Python 开发规范

1. 使用独立虚拟环境，开发、测试和生产保持相同的 Python 次版本；版本和类库按[选型记录](../.agents/memory/decisions.md)确认，不提前安装。
2. 按接口、数据模型、业务逻辑和 OCR 适配划分职责，测试独立存放；具体目录随技术方案确定，不创建空层。
3. 遵循 PEP 8，使用 4 个空格缩进、UTF-8 编码和 100 字符行宽；检查与格式化工具在选型后统一配置。
4. 模块、函数和变量使用 `snake_case`，类使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`；使用绝对导入，禁止通配符导入。
5. 函数保持单一职责，参数和返回值添加类型标注；不使用可变默认参数，不用 `assert` 校验业务输入。
6. 在接口边界校验请求与响应，路由层不编写识别业务逻辑，业务层不直接依赖某个 OCR 厂商的返回结构。
7. 与 Java 端确认字段、类型、空值、错误码和接口版本；金额使用 `Decimal` 处理，传输格式按接口契约确定，日期使用 ISO 8601。
8. 缺失的识别结果不伪造，低质量结果与服务异常分别处理；统一异常响应，不吞掉异常，不暴露内部堆栈。
9. 校验图片真实格式、文件大小和解码后像素数；图片 URL 使用受控来源，校验 DNS 与实际连接地址，阻止非授权内网、回环及云元数据访问，默认关闭重定向。
10. 下载设置超时和实际字节数上限；推理设置处理时限，并发与队列有界，禁止在异步事件循环中直接执行阻塞推理。
11. 本地 OCR 模型在应用生命周期中加载并记录版本，不在请求中下载模型；未确认线程安全前，不共享引擎实例并发推理。
12. 配置集中管理并在启动时校验，密钥不写入代码；示例配置只保留占位符。
13. 日志记录请求标识、处理阶段、耗时和错误码；禁止记录原图、完整票据文本、密钥及带签名参数的 URL。
14. 接口设置访问控制和限流；临时文件使用随机名称并及时清理，原图默认不长期保存，文件和连接及时释放。
15. 测试覆盖正常流程、字段解析、非法图片、下载失败和引擎异常；使用脱敏样本做 OCR 回归，并验证 Java 接口契约。
16. 提交前执行已配置的检查和测试，如实说明未执行项；不提交虚拟环境、缓存、模型大文件、日志、客户票据及个人 IDE 配置。
17. 每次提交只处理一个逻辑变更，提交信息使用 `feat:`、`fix:`、`docs:` 等前缀；同步更新接口文档、配置说明和相关测试。
