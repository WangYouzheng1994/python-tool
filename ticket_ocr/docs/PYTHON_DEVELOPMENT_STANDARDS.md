# Python 开发规范

1. 使用独立虚拟环境，通过 `pyproject.toml` 管理项目，使用 `uv` 管理依赖并提交锁文件，开发与生产保持相同的 Python 次版本。
2. 采用 `src/ticket_ocr/` 布局，接口放 `api/`，数据模型放 `schemas/`，业务逻辑放 `services/`，OCR 适配放 `engines/`，测试放 `tests/`。
3. 遵循 PEP 8，使用 4 个空格缩进、UTF-8 编码和 100 字符行宽，统一使用 Ruff 检查和格式化。
4. 模块、函数和变量使用 `snake_case`，类使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`；使用绝对导入，禁止通配符导入。
5. 函数保持单一职责，参数和返回值添加类型标注；不使用可变默认参数，不用 `assert` 校验业务输入。
6. 使用 FastAPI 提供接口，使用 Pydantic 校验请求和响应；路由层只处理协议与参数，不编写识别业务逻辑。
7. 文件上传使用 `multipart/form-data`，图片 URL 使用 JSON；接口统一使用 `/api/v1/` 前缀，并维护 OpenAPI 文档。
8. 与 Java 端统一字段、类型和错误码；JSON 字段使用 `snake_case`，缺失值返回 `null`，金额使用 `Decimal` 处理并以字符串返回，日期使用 ISO 8601。
9. 统一处理异常，返回错误码、消息和请求标识，使用正确的 HTTP 状态码；禁止吞掉异常或向调用方暴露内部堆栈。
10. 校验图片真实格式、文件大小和解码后像素数；URL 下载使用受控域名白名单，校验 DNS 与实际连接地址，阻止非授权内网、回环及云元数据访问，默认关闭重定向。
11. 下载设置超时和实际字节数上限；推理设置处理时限，并发数与队列容量设上限，禁止在异步事件循环中直接执行阻塞推理。
12. OCR 模型在应用生命周期中加载并记录版本，不在请求中下载模型；未确认线程安全前，不共享引擎实例并发推理。
13. 配置通过环境变量集中管理并在启动时校验；密钥不写入代码，`.env.example` 只保留占位符。
14. 使用结构化日志，记录请求标识、处理阶段、耗时和错误码；禁止记录原图、完整票据文本、密钥及带签名参数的 URL。
15. 接口启用认证和限流；临时文件使用随机名称并及时清理，原图默认不长期保存，文件和连接使用上下文管理器释放。
16. 使用 pytest 覆盖正常流程、字段解析、非法图片、下载失败和引擎异常；使用脱敏样本进行 OCR 回归，并验证 Java 接口契约。
17. 提交前通过 Ruff、mypy 和 pytest 检查；不提交虚拟环境、缓存、模型大文件、日志、客户票据及个人 IDE 配置。
18. 每次提交只处理一个逻辑变更，提交信息使用 `feat:`、`fix:`、`docs:` 等前缀；同步更新接口文档、配置说明和相关测试。
