## 3. 神经网络究竟怎样训练

### 3.1 网络结构、损失与优化器各做什么

1. **结构 architecture**规定层和连接、数据如何流动、哪些参数存在；**权重 weights**是这些参数的具体数值。同一个结构训练两次，可以得到不同权重。
2. **前向传播 forward**用当前参数计算预测；**损失 loss**把预测与目标的差异转成可优化的量。分类、检测、序列识别的损失可以不同，一个模型也可能组合多个损失。
3. **梯度 gradient**描述损失对参数变化的局部敏感性；**反向传播 backpropagation**通过链式法则计算这些梯度。自动求导框架负责大量细节，不是程序员手工逐个试参数。
4. **优化器 optimizer**根据梯度和状态更新参数。最简单的示意是 `w_new = w_old - learning_rate * gradient`；Adam、带动量 SGD 等还有额外状态和规则。
5. 训练是在目标函数约束下进行数值优化，不是无目标的“概率乱撞”。随机性主要来自初始化、抽样和正则化等；梯度提供方向，但非凸问题通常不保证找到全局最优，更不保证业务准确率完美。
6. loss 降低不等于真实业务改善：模型可能记住训练数据，也可能优化了与业务不完全一致的代理目标。最终必须检查独立数据上的任务与业务指标。

### 3.2 一轮训练里发生什么

```text
定义任务、网络、loss 与优化器 → 初始化参数或加载预训练权重
→ 读取训练 batch 及目标 → 前向预测 → 计算 loss → 清理旧梯度
→ 反向传播 → 优化器更新可训练参数 → 记录指标
→ 持续处理 batch → 按计划验证并保存 checkpoint → 选择模型
```

| 术语 | 含义与实际影响 |
| --- | --- |
| sample | 一条训练样本；检测通常是一张图片及区域标签，识别可以是文字行图块及转写 |
| batch size | 一次参数更新使用的样本量，影响显存、梯度估计、速度及训练行为 |
| step/iteration | 通常指一次更新或一次迭代；梯度累积时读取 batch 与更新次数不同，需看实现 |
| epoch | 通常表示遍历训练集一轮；重复采样、流式数据等情况要明确项目定义 |
| learning rate | 更新步长；过大可能震荡或破坏预训练能力，过小可能收敛慢或学习不足 |
| scheduler | 按训练进度调整学习率，例如预热与衰减 |
| initialization | 参数初值；随机初始化有合理尺度，不是任意填数；微调通常加载既有权重 |
| hyperparameter | 人设定或搜索的配置，如学习率、batch、增强；区别于训练学到的参数 |
| regularization | 限制过拟合的方法，如权重衰减、增强、dropout；不是越强越好 |

1. 训练模式与评估模式可能影响 dropout、BatchNorm 等层的行为；推理通常关闭 dropout 并使用适合评估的状态，不能只认为“不调用 optimizer 就万事相同”。
2. 参数更新需要保存用于反传的中间信息，还可能保存梯度、动量等，因此训练内存开销通常大于同模型推理。不能按部署文件大小直接估算训练显存。
3. 数据增强改变训练输入，例如亮度、轻微旋转、模糊；必须保留任务语义与正确标签，不能把小数点抹掉后仍当可靠标注。

### 3.3 训练与推理的边界

| 对比项 | 训练/微调 | 推理 |
| --- | --- | --- |
| 输入 | 数据、目标、结构、配置，微调还需要初始权重 | 新图片/文本、部署模型和配套配置 |
| 核心行为 | 前向、loss、反传、优化器更新 | 通常只前向、解码和后处理 |
| 输出 | 权重、checkpoint、指标和实验记录 | 文字、框、分数或 token 等 |
| 是否学习 | 更新可训练参数 | 正常使用不更新权重 |
| 当前项目 | 未训练或微调 | CPU OCR 加业务字段规则 |

多识别几张图片、保存 JSON、调整阈值、增加业务规则都不自动构成训练。只有另外建立经授权的数据反馈与训练发布流程，才能让未来模型通过这些样本学习。

## 4. 训练集、验证集、测试集与泛化

### 4.1 标签与学习方式

1. **监督学习**使用样本和目标标签：检测标签是文字区域/多边形等；识别标签是对应图块的准确转写；字段抽取标签还可能包括字段类型、值及关系。
2. **自监督学习**从数据自身构造目标，例如遮蔽恢复、对比学习、预测下一 token；不是没有训练目标，也不是所有原始数据都不用治理。
3. **无监督学习**关注无显式人工目标标签的数据结构，如聚类；**半监督学习**结合少量标注与大量未标注；**强化学习**围绕行为和奖励优化。这些概念不能统称为 OCR 微调。
4. 数据集可以是图片、标签、划分清单和使用协议的组合；不是只收集一个图片文件夹。需要统一标注规范、版本和授权记录。

### 4.2 三个集合不能混用

| 集合 | 用途 | 不该做什么 |
| --- | --- | --- |
| 训练集 train | 用于更新权重 | 不能用其高准确率证明泛化 |
| 验证集 validation/dev | 调参、选 checkpoint、早停 | 反复选择会对它形成间接适配，不能冒充最终独立测试 |
| 测试集 test | 冻结方案后评估最终表现 | 不能反复看错误再据此调参，还声称完全独立 |

1. **数据泄漏**不仅是同一个文件同时出现。相同票据的连续拍摄、裁剪、增强版本，或高度重复的同批模板，都可能让测试虚高；应按来源、批次、设备或时间等分组拆分。
2. **泛化**是对未见且具有代表性的数据仍有效；**过拟合**是训练表现很好、独立数据表现差；**欠拟合**是训练本身也学得不足。增加 epoch 不能保证解决问题。
3. 数据质量包括标注准确、覆盖面、困难样本、类别比例、清晰度和采集分布。盲目增加近重复图片，不如修正错误标签与补齐目标场景。
4. 测试要覆盖实际部署分布：字体、分辨率、设备、反光、倾斜、语言、小数点、负号、单位及多组字段。只看平均值会掩盖关键场景退化。
5. 样本数量没有统一门槛；取决于变化范围、预训练基础、目标错误率与标注质量。少量成功样本只能证明可运行，不能证明低错误率。
6. 原图和标签可能敏感；先明确采集、标注、训练、保存及分发授权。模型不逐条保存原图，并不意味着完全没有记忆或泄漏训练信息的可能。

<a id="sec-5"></a>
## 5. 为什么同样训练不一定得到同样权重

### 5.1 “数据、超参数和硬件相同”还不充分

1. 随机初始化可能不同；样本 shuffle 顺序、数据增强随机数、dropout 掩码、多进程数据加载顺序也可能不同。
2. GPU 并行归约和部分算子可能非确定；浮点加法不满足精确结合律，计算顺序差异可以产生微小数值差异，再在多次更新中放大。CPU、多线程和不同库版本也不天然保证逐位相同。
3. 框架、驱动、CUDA、算子库、编译优化、混合精度与分布式通信配置都可能影响轨迹。相同型号硬件不等于完整环境相同。
4. 多组权重可能达到相近效果；权重不相同不代表训练失败，也不能只因效果接近就说完全复现。

### 5.2 可复现不是不可能，而是要定义级别

| 复现目标 | 要求 | 判断方式 |
| --- | --- | --- |
| 逐位复现 bitwise | 参数及相关输出二进制一致 | 明确范围后比较哈希或逐元素位级结果 |
| 数值接近 | 允许受控浮点误差 | 定义绝对/相对误差与比较对象 |
| 效果复现 | 在代表性数据上取得相近指标 | 固定评估协议，报告多次运行及波动 |

1. 记录代码提交、数据版本及划分、完整配置、依赖、设备和精度策略；给 Python、数值库、框架和数据加载等相关随机源设 seed。
2. 启用框架支持的确定性算法，控制线程、并行策略和加载顺序；部分设置会降低性能或因无确定性算子而报错。固定 seed 是必要手段之一，不是跨环境的万能保证。
3. 从同一初始 checkpoint 开始，比“都用了同名模型”更严格。要原样续训，还需要相同 optimizer 状态、学习率 scheduler、步数、随机数状态、混合精度状态和数据进度等；只有权重通常不够。
4. 在所有相关条件受控且操作确定的范围内，可以追求确定性结果；跨平台、跨框架、跨版本通常应先定义容差和效果复现标准，而非承诺逐位一致。
