## 13. LLM、VLM 与 OCR 的关系

### 13.1 共同原理，不同任务

1. 这些模型都可以使用神经网络、loss、反向传播和优化器，但结构、数据、目标、规模和解码方式不同。使用 Transformer 不代表就是通用大语言模型。
2. 纯文本 LLM 处理文本 token，不能凭空直接读取图片；系统若能收图，可能额外接了 OCR、视觉编码器或 VLM。VLM 把视觉与语言结合，可做图像问答、文档理解或转写等。
3. 自回归模型逐个生成 token，后一 token 依赖前文；不是所有 OCR 都自回归，也不是所有神经网络都是生成式模型。CTC OCR 与自回归文档模型要按具体机制区分。
4. 模型更大不代表票据数字更可靠。生成式模型可能补全、改写或输出看似合理的内容；专用 OCR 也会误识别。原图证据和独立校验都不能省。

### 13.2 大模型同样有训练与推理

| 阶段/机制 | 做什么 | 是否本身更新权重 |
| --- | --- | --- |
| 预训练 | 通过下一 token 预测等目标学习一般能力，目标因模型而异 | 是 |
| 后训练 | 监督微调、偏好优化等，使行为更适合任务与交互 | 是，具体机制不同 |
| 推理生成 | 根据输入与已生成内容计算输出 | 通常不更新 |
| context 上下文 | 提供本次计算可参考的信息 | 否 |
| KV cache | 缓存注意力计算中相关键值，减少重复计算 | 否 |
| RAG | 检索资料并作为上下文输入 | 检索与拼上下文本身不更新 |

1. token 不一定等于一个汉字或单词；上下文长度、KV cache 和训练参数是不同资源。
2. 回答里有多步“推理”不等于正在训练；增加计算时间不等于更新权重。当前会话参考新材料，不等于永久学入参数。
3. RAG 系统可以另外训练检索器或模型，但那是额外训练流程；仅检索数据库、保存对话、增加规则，不叫微调。
4. 普通模型不会越用越自动聪明。产品若将反馈另行用于后续训练，需要独立的数据授权、治理、评估和模型发布流程，不能与当前在线推理混为一谈。
