## 6. 预训练、微调与从零训练

### 6.1 四种工作量不是一回事

| 方式 | 起点与做法 | 主要门槛 |
| --- | --- | --- |
| 使用预训练模型推理 | 取得别人已学好的权重及配套制品，直接运行 | 环境、前后处理、适配与业务评估 |
| 微调 fine-tuning | 从已有权重继续训练全部或部分参数 | 领域数据、标注、实验和导出验收 |
| 从零训练 from scratch | 用现有框架和网络实现，从初始化参数训练 | 更多数据、计算和训练经验 |
| 从零造框架/算法 | 自己实现自动求导、算子系统，或设计新算法 | 系统研发/算法研究，不是普通模型训练的必要步骤 |

1. 预训练表示模型此前已在某数据与目标下学习过；不是“天然通用且适合所有票据”。预训练数据、许可和能力范围仍需核对。
2. 微调可以冻结骨干、只训练输出头，也可以逐步解冻或训练全模型。**冻结**指这些参数不参与优化更新，不代表跳过相关前向计算；BatchNorm 等状态是否更新还需配置训练模式。
3. 调阈值、改字典、改提示词、写字段规则不是微调。新增字符可能改变输出层维度及已有类别映射，不能只加一行字典便声称学会新字符。
4. 部署用 ONNX 不必然是合适的续训起点。通常应取得对应训练框架可加载的权重、网络配置和代码，再开始微调。

### 6.2 微调完整流程

1. **确定目标**：区分检测漏框、识别错字和字段错配；定义部署资源、关键数字指标、拒绝率与人工复核边界，保存现有基线。
2. **准备授权数据**：采集代表性和困难场景，制定标注规范与质量抽查；检测标区域，识别标图块转写，业务字段另有关系标签。
3. **拆分数据**：按来源/批次/时间分组防泄漏，冻结测试集；增强只在适当训练阶段使用，不把增强副本跨集合。
4. **匹配训练制品**：确认代码、框架、结构、初始权重、字典、输入尺寸和数据格式；保留版本及许可。
5. **设计实验**：设置学习率、batch、epoch、增强、冻结范围和随机种子；先做小规模可运行性及数据检查，再扩大，不把“跑起来”当验收。
6. **监控与选择**：同时看训练和验证指标，检查过拟合、困难子集及旧场景退化，合理早停与保存 checkpoint；不拿最终测试集不断挑模型。
7. **独立验收**：固定方案后在测试集报告任务指标、业务整串匹配率、错误分类和人工复核率，明确样本量与分布。
8. **导出与转换**：生成推理模型，必要时转 ONNX；检查算子、动态形状、精度和字典，比较转换前后输出。
9. **目标环境回归**：在部署 CPU/GPU、运行时和完整流水线上验证准确率、字段、延迟、内存及吞吐；保留旧制品、回滚和审批记录。

### 6.3 技术和硬件门槛

1. 推理接入需要图像处理、依赖环境、配置、返回结构和服务工程能力；微调增加数据治理、神经网络基础、框架训练、评估和实验追踪；算法研发还增加数学与论文复现能力。
2. 训练通常用 GPU 更实用，但 CPU 训练不是理论上不可能；需要的显存取决于网络、图片尺寸、batch、序列长度、精度与优化器，不能一口承诺某固定显存就够。
3. GPU 训练的模型可以导出后在 CPU 推理，训练硬件不强制绑定部署硬件；但目标运行时必须支持相应算子和数值格式，并重新评估速度及效果。
4. 不需要先自造训练框架，也不需要一开始就学习全部算法。对当前项目，应优先掌握可复现推理、错误分层与业务验收，再决定是否投入标注和微调。

## 7. 训练框架及行业使用口径

### 7.1 PyTorch、PaddlePaddle、TensorFlow 是同一层的框架

| 框架 | 共同职责 | 生态理解 |
| --- | --- | --- |
| PyTorch | 张量、自动求导、神经网络、优化器、设备计算等 | 全球研究和许多现代模型开发生态中更主流，相关资料和模型通常丰富 |
| PaddlePaddle（飞桨） | 同类训练开发能力，并有自己的执行、算子及部署体系 | 百度发起的独立深度学习框架，PaddleOCR 是其重要任务生态之一 |
| TensorFlow | 同类建模训练能力，并有自己的部署工具生态 | 长期积累了研究、工业与端侧部署工具，具体价值看项目栈 |

1. 三者不是互相必须调用的上下游。PaddlePaddle 不是 PyTorch 的简单封装，也不是“把 PyTorch 改名”。不同框架可以表达相近数学运算，却拥有各自的接口、执行与模型格式。
2. 独立框架不等于每行代码、每个数学方法都原创。框架会复用通用数学、BLAS、CUDA/cuDNN 等底层能力及开源组件；使用共同基础库不意味着它们互为封装。CUDA 是 NVIDIA 的并行计算平台，不是 OCR 模型或训练框架。
3. 训练框架往往也能推理，不是只能训练；推理部署还可选择框架自带引擎或导出到其他运行时。不要把“训练用 Paddle”误解为“部署必须安装完整 Paddle”。
4. 选框架应看目标算法/预训练权重、训练代码成熟度、部署路径、团队能力、维护与许可。当前使用 PP 系模型，不意味着为了跟随全球趋势就必须重写成 PyTorch。

### 7.2 “行业认可”“市场份额”要先问统计口径

1. 可以定性说 PyTorch 在全球研究与很多新模型生态中更主流，但本轮没有核实可用于统一排名的百分比，不给出虚构采用率。
2. 论文出现次数反映研究使用，不直接等于商业收入、生产部署数量或企业认可度。下载量、GitHub star、招聘需求、调查问卷也各有偏差。
3. 调查应注明年份、地区、样本群体、统计单位与是否多选；多选比例相加可能超过 100%。中国企业样本与全球论文样本不能直接拼成一个份额。
4. “全球更主流”不等于每个具体任务更优；“某 OCR 项目成熟”也不证明其底层框架占全球第一。按具体版本与任务评估，避免从地域或品牌推导精度。
