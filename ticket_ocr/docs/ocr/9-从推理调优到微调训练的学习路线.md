# 9. 从推理调优到微调训练的学习路线

[总目录](../OCR_TECHNICAL_OVERVIEW.md) · [上一篇](8-术语误区与参考索引.md)

## 1. 目标、边界与路线选择

1. 面向资深 Java 后端、Python/机器学习新手。已有接口、并发和发布经验可以复用，但张量、图像、实验统计和训练不是 Java API 的简单换名。
2. 默认每周投入 **8–10 小时**。下表是主动学习、练习和复盘预算，不是生产交付工期；不含数据授权等待、大规模标注、设备排期、长训练等待和服务化。实际速度取决于基础和错误复杂度，不保证按期达标。
3. **必学推理主线：A → B → C → D**。达到目标可以在 D 停下，进入工程验收；不需要为了调推理线程而学完整训练框架。
4. **按需训练支线：E → F → G**。B/C/D 的错误证据证明需要更新模型，且有数据与计算授权后才进入。漏框优先研究检测，完整框内错字优先研究识别；文字对而字段关联错，应先改规则，不训练模型掩盖关联缺陷。
5. **最短按需路径**：A–D → E 的最小通用训练基础 → F 选择检测或识别之一 → G。E 只用小教程理解张量、自动求导、训练循环、验证和保存，可直接使用 Paddle 教程；无需先安装或学习 PyTorch，也不要求同时安装两套训练框架或重写 PP-OCR。已有这些能力可直接用验收证明后跳过对应练习，时间另记，不混用下表完整预算。
6. 可选扩展：深入 PyTorch、论文、分布式训练、量化感知训练、蒸馏、VLM 和算法研发，均不计入下表，不是第一次 PaddleOCR 微调的先修硬门槛。
7. 本文只安排未来实践，不宣称当前项目已实现评测、训练或性能优化。安装框架、下载教程数据/模型、访问真实原图或 OCR JSON、使用 GPU/外部服务前，另行确认授权；本轮没有执行这些操作。不要将敏感图片上传到教程、云 Notebook 或公共仓库。

## 2. 时间总表与每周节奏

| 阶段 | 路径 | 主动投入 | 按每周 8–10 小时折算 | 里程碑 |
| --- | --- | --- | --- | --- |
| A Python、NumPy 与图像 | 必学 | 16–20 小时 | 1.6–2.5 周 | 能解释并检查像素到张量 |
| B 基准与错误分类 | 必学 | 16–24 小时 | 1.6–3 周 | 固定数据划分和评测协议 |
| C RapidOCR 参数与前后处理 | 必学 | 24–32 小时 | 2.4–4 周 | 有可复现实验及回退结论 |
| D ORT 性能与模型替换 | 必学 | 24–32 小时 | 2.4–4 周 | CPU 端到端准确率/性能联合报告 |
| E 通用深度学习与最小训练循环 | 按需 | 24–32 小时 | 2.4–4 周 | 能解释并复现一个最小训练循环 |
| F PaddleOCR 单模块微调 | 按需 | 32–48 小时 | 3.2–6 周 | 一个有验证证据的候选 checkpoint |
| G 导出、字典与 CPU 回归 | 训练必配 | 16–24 小时 | 1.6–3 周 | 可追溯、可回滚的部署候选包 |
| A–D 合计 | 推理主线 | **80–108 小时** | **8–13.5 周** | 不以学习结束代替业务验收 |
| E–G 合计 | 训练支线增量 | **72–104 小时** | **7.2–13 周** | 只含一个模块的首次学习实验 |
| A–G 合计 | 主线加训练支线 | **152–212 小时** | **15.2–26.5 周** | 不含可选扩展和生产落地 |

1. 周数范围统一为“最低小时数 ÷ 10 ～ 最高小时数 ÷ 8”，不是把某个固定周数再乘一个平均值。依序串行学习可据此安排；日历按整周预约时向上取整：主线约 8–14 周，全程约 16–27 周。各阶段上取整再相加会更保守，不应反推为新的工时总计。
2. 每周安排四个 **2 小时实践单元**：①读官方教程并做一个最小例子；②在合成数据上复现；③做一次受控实验；④整理证据与失败原因，共 8 小时。可增加一个 2 小时复盘/补课单元，达到 10 小时。单元顺延即可，不要求每周完成一个阶段。
3. 阶段可以按 2–3 小时拆分：如 3+3+2=8 小时，或 3+3+2+2=10 小时；不要把连续训练等待当作有效学习时长。最小一周模板：周二 2 小时学概念、周四 2 小时复现、周六 2–3 小时实验、周日 2–3 小时复盘，共 8–10 小时。
4. 里程碑不是日期承诺：A 完成输入审计；B 冻结评测规则；C 有调参对照；D 决定是否需要训练；E 通过训练基础验收；F 选择候选；G 完成 CPU 回归或明确拒绝发布。未过验收时延长该阶段，记录实际工时。

## 4. 阶段 A：Python → NumPy → 图像（16–20 小时）

1. **前置**：已有 Java 的函数、集合、异常和模块概念；不要求机器学习基础。读[行业与张量](1-行业与机器学习基础.md#sec-1)、[图片输入](1-行业与机器学习基础.md#sec-2)。
2. **学什么**：Python 列表/字典、迭代器、路径、上下文管理器、模块入口、类型提示和异常；避免把可变对象、引用、切片视图当成 Java 值拷贝。NumPy 学 `shape`、`dtype`、索引、广播、轴、矩阵乘与逐元素乘的区别、复制/视图、uint8 溢出。图像学 RGB/BGR、透明底、EXIF、插值、保宽高比、补边、NCHW/NHWC 和归一化。
3. **看哪里**：T1 的数据结构/模块/异常/文件，T2 的基础/广播/视图，T3 的图像基本操作/几何变换；对照[OCR 流程](4-OCR体系与模型制品.md#sec-10)。
4. **工时分配**：Python 6–8 小时，NumPy 6–8 小时，图像实验 4 小时，合计 16–20 小时。
5. **当前项目练习**：只读入口与 Demo 的数据流，画在个人草稿中的文字调用链即可；先用自行生成的非敏感棋盘格、带小数点图块和透明图片，比较尺寸、通道、像素和归一化结果。不要为了学习直接重构现有 Demo。后续代码练习须按任务单独安排，不把本文当修改授权。
6. **输出/验收**：一份输入审计表和最小可重复练习，能说明一张图每步形状/类型/数值范围，解释透明底和方向对坐标的影响；能检查“除以 255 两次”“把 RGB 当 BGR”“切片修改原数组”的错误。不能解释时先补基础，不进入盲调参数。
7. **条件/误区**：CPU 足够，GPU 无必要。先复用已批准环境；OpenCV 若不在当前环境，先读教程，未来申请独立练习环境，不为文档安装依赖。图像数字化不是量化；锐化不保证恢复原始信息。

## 5. 阶段 B：评测基准与误差分类（16–24 小时）

1. **前置**：A 验收通过；能看懂 OCR 框、文字和分数。读[数据划分](2-训练原理与数据集.md#sec-4)、[诊断验收](5-推理运行时与性能精度.md#sec-14)。
2. **学什么**：precision/recall、CER 的编辑距离、文字行和数字整串正确率、字段精确匹配、拒绝率与自动接受错误率；明确多组配对和空值怎么算。区分漏检、裁剪、方向、错字、字典、排序、字段规则和服务错误。学习样本量、分母和子集分布，不只报一个平均值。
3. **看哪里**：T8 的 detection/recognition evaluation 与 dataset preparation；T2 的数组统计。业务字段评测需按本项目契约另定义，官方 OCR 指标不替代它。
4. **工时分配**：指标与错误分类 4–6 小时，数据授权/划分方案与标注规范练习 6–10 小时，基准计算和复核 6–8 小时，共 16–24 小时；真实授权等待与批量标注不在此预算。
5. **当前项目练习**：先用合成数据编写评测规格，列明标签和值错配、小数点丢失、多组、缺失、低分和歧义案例；取得明确访问授权后，才在本地复核原图与 JSON。按来源/批次分组，锁住最终测试集；调参只看开发/验证集，不反复偷看最终测试集。
6. **输出/验收**：版本化的非敏感评测规范、划分清单方案、基线摘要和错误矩阵；能由另一人按同一规则重算相同分子/分母，知道每种失败归哪一阶段。当前尚未目视核验的历史结果不能当真值，`status: ok` 不是正确标签。
7. **条件/误区**：CPU 足够；初期无需跑模型也能验证指标实现。没有授权样本只能完成合成演练，不能宣布业务基准成立。不给统一“必须多少张”的保证；根据目标错误率、分布覆盖和风险决定采样，记录不足。

## 6. 阶段 C：RapidOCR 参数与前后处理（24–32 小时）

1. **前置**：B 的评测协议和基线可复现。读[SDK 分层](4-OCR体系与模型制品.md#sec-8)、[流程](4-OCR体系与模型制品.md#sec-10)、[差异原因](5-推理运行时与性能精度.md#sec-12)。
2. **学什么**：检测尺寸上限、阈值、框扩张及文字过滤的召回/误检权衡；裁剪、透视、方向开关、识别批量、字典与 CTC。分清候选配置名称和当前版本真正接受的参数；字段低分规则与 OCR 过滤是两个层次，不应同时改而失去归因。
3. **看哪里**：T4 对应 tag 的配置与文档、T3 几何变换和阈值教程。先找到 RapidOCR 3.10.0 的参数定义与默认值，再制定实验表；不假定最新文档中的参数当前存在。
4. **工时分配**：配置与流程追踪 6–8 小时，前处理/裁剪实验 6–8 小时，单变量对照 8–10 小时，复盘与回退 4–6 小时，共 24–32 小时。
5. **当前项目练习**：未来在独立实验配置中逐项比较尺寸、检测/过滤阈值、方向开关；固定模型/字典 hash、输入划分和其余配置。每次记录改动理由、各错误子集指标和完整耗时边界，观察小数点是否被裁掉。先修输入和几何，不用规则把字母无证据猜成数字。若需要暴露新参数，另列代码任务，不在学习文档中宣称已支持。
6. **输出/验收**：基线与至少一个候选的可重复对照表、失败案例分类摘要和回退配置；改进结论必须同时报告拒绝率、自动接受错误率、关键整串和延迟。有改善才保留，没有改善也应能定位原因。最终测试集留到冻结候选后使用。
7. **条件/误区**：当前 CPU 可做；GPU 不是调参前提。增加输入尺寸可能增延迟/内存，降低阈值可能增加误检；0/180 度分类不等于任意纠偏。不能凭一个样本挑“最佳阈值”，也不能把调阈值叫微调。

## 7. 阶段 D：ORT 性能分析与模型替换（24–32 小时）

1. **前置**：C 有可追溯配置与评测。读[模型制品](4-OCR体系与模型制品.md#sec-9)、[运行时](5-推理运行时与性能精度.md#sec-11)、[模型来源](7-模型来源与项目交付.md#sec-15)。
2. **学什么**：session 生命周期、EP 实际启用和算子回落、线程竞争、图优化、动态形状、batch、内存复制和 profiling。区分初始化、模型计算、完整流水线及写盘；固定预热方式、重复次数，记录分位数和吞吐，不把单图耗时倒数当生产 QPS。了解量化，但不急于用 INT8 替代基线。
3. **看哪里**：T5 的 Python/EP/Thread management/Profiling/Graph optimizations，T4 的模型适配说明。模型替换前按 T8/T4 核查任务、语言、输入输出、字典、归一化、许可和转换支持。
4. **工时分配**：ORT 概念与 profiling 6–8 小时，CPU 线程/计时对照 8–10 小时，模型替换兼容检查 6–8 小时，回归报告 4–6 小时，共 24–32 小时。
5. **当前项目练习**：在未来获准实验中先测现有 CPU 配置，分冷启动/稳态与 Det/Rec 工作量；保持同一准确率目标比较线程与批量。仅在确认资源下载和许可后，选一个受支持候选替换出问题的模块，连同字典/配置成套管理，不覆盖已验收旧文件。单独 ORT 执行成功不等于 RapidOCR 解码适配正确。
6. **输出/验收**：环境、模型/字典 hash、provider、线程、batch、计时范围、关键字段/整串、拒绝率、延迟分位数、内存及波动齐全；另有替换兼容清单和回滚步骤。若只改善模型计算而端到端无改善，结论明确“不采纳”或解释业务收益。最终冻结候选再用测试集验收，失败应恢复开发集重新设计，不能继续调测试集。
7. **条件/误区**：CPU 主线即可完成。GPU 实验需另核对驱动、CUDA/cuDNN、ORT 包与 EP 支持，记录回落和传输开销；本阶段不保证 GPU 更快。性能 profiling 本身可能引入开销，应与正式计时分开。
8. **转训练决策**：只有错误集中在稳定的检测或识别能力缺口、采集/适配/参数/适用预训练模型仍不足，且存在授权训练数据时才进入 E–G。若主要是字段配对，先回到规则与业务契约；若没有计算和数据条件，输出阻塞清单，不靠训练口号替代方案。

## 8. 阶段 E：通用深度学习与最小训练循环（24–32 小时，按需）

1. **前置**：A 的张量操作；B 的数据划分。数学补到矩阵乘、函数导数、链式法则、均值/方差与概率解释即可开始。读[训练原理与复现](2-训练原理与数据集.md#sec-3)、[微调和框架](3-训练框架与模型微调.md#sec-6)。
2. **学什么**：前向、loss、梯度、反传、optimizer、学习率、batch/epoch、训练/评估模式、过拟合、增强、seed、checkpoint 与续训状态。知道 CNN 处理空间、CTC 处理不对齐序列的基本职责；暂不要求手推全部架构或造自动求导框架。
3. **看哪里**：面向后续 PaddleOCR 微调，可直接选 T7 的张量/数据加载/建模/自动求导/优化/保存加载教程完成通用基础；T6 Learn the Basics 是可选替代，不是先修课。二选一即可，不必安装两套框架；选择 PyTorch 练习也不表示将当前 PP 系模型迁移成 PyTorch。
4. **工时分配**：数学与通用原理 6–8 小时，所选框架的最小训练循环 10–14 小时，模式/复现/checkpoint 与 Paddle 接口理解 8–10 小时，共 24–32 小时；直接用 Paddle 时在同一框架内完成，不额外安排第二套框架练习。
5. **当前项目练习**：未来在隔离练习环境用合成或许可明确的公开小数据做小分类任务，观察前向/反传前后参数差异，保存/恢复模型，制造过拟合再解释验证指标。对照项目正常推理为何不更新参数；不把敏感票据作为第一份教程数据。
6. **输出/验收**：能逐步说明一个最小循环，证明训练更新权重、评估不更新，说明清梯度、`train`/`eval` 和不记录梯度的区别；能恢复并比较同一输入输出，说明只有权重为什么不能保证原样续训。loss 下降但验证变差时知道停下来查数据。
7. **条件/误区**：小例子 CPU 足够；完整 OCR 训练资源另评估。需安装所选训练框架时单独授权并隔离，不动当前推理依赖。可只用 Paddle 完成 E 并进入 F，无需安装 PyTorch；也没有必要先学完所有框架 API、分布式或生成式模型。真正的门槛是上述通用概念验收。

## 9. 阶段 F：按需 PaddleOCR 检测或识别微调（32–48 小时）

1. **前置**：D 的训练决策通过，E 的通用知识具备；有数据许可、代表性划分和资源预算。读[微调完整流程](3-训练框架与模型微调.md#sec-6)及[当前制品边界](7-模型来源与项目交付.md#sec-16)。
2. **学什么**：Paddle 张量/梯度/优化器的接口，目标 PaddleOCR 版本的 YAML 配置、数据加载、预训练权重、学习率、batch、增强、冻结和评估/保存策略。现有部署 ONNX 不作为默认续训 checkpoint；先取得匹配的训练代码、结构和原框架权重，核查许可与来源。
3. **选择一条任务线**：
   - **检测线**：针对漏框、粘连、截断，学多边形标注、忽略区域、检测增强、precision/recall 与后处理影响；评测既看检测也看后续文字/字段，避免召回升但误框暴涨。
   - **识别线**：针对正确完整图块里的错字，学文字行裁剪、准确转写、语言/字典、输入尺寸、特殊符号、CTC blank 与输出头维度；单图块指标之外还要检查全流水线。新增字符不只是追加字典，输出头和训练策略需匹配。
4. **看哪里**：T7 的张量/自动求导/optimizer/保存加载；T8 对应版本的 data preparation、detection 或 recognition training、fine-tuning、evaluation。先跟维护中的官方配置跑一个最小实验，不照搬其他版本命令。
5. **工时分配**：Paddle/版本与配置对应 6–8 小时，数据格式/标注抽查与划分演练 10–16 小时，训练/验证/错误诊断 12–18 小时，选候选与实验整理 4–6 小时，共 32–48 小时。只覆盖一个模块的学习实验，若两模块都训需要新增预算；实际数据生产和长训练等待另算。
6. **当前项目练习**：未来用授权数据建立训练专用清单，先检查读图、标签和小批前向，再做小规模过拟合排错，随后按验证集决定学习率/早停和候选。固定测试集，不用它选 checkpoint。保留原模型基线，检查旧场景退化；数据与实验权重留在受控位置，不提交真实素材。
7. **输出/验收**：可追溯的代码/配置/数据版本、初始化权重来源、随机种子、训练/验证曲线、任务与业务子集指标、候选 checkpoint 和失败结论。与基线比较须报告样本量/分布、拒绝率和风险，训练 loss 降不算通过；没有改善可以停止，不必为了“训练完成”发布。
8. **条件/误区**：正式 OCR 微调通常 GPU 更实用；显存由模型、尺寸、batch、精度和 optimizer 决定，先做小批资源测量再预算，不保证固定显存、数据量或准确率。CPU 可读配置、检查数据及做部分小型演练，但不承诺完整训练的可接受时长；没有 GPU 时可在此交付数据/配置审查与阻塞说明，不能写成训练验收通过。

## 10. 阶段 G：导出、字典、ONNX 兼容与 CPU 回归（16–24 小时）

1. **前置**：F 有经验证的候选和原框架推理基准；当前部署路径仍是 CPU OCR。读[ONNX 与制品](4-OCR体系与模型制品.md#sec-9)、[资源交付](7-模型来源与项目交付.md#sec-16)。
2. **学什么**：checkpoint → 推理导出 → 必要的 Paddle2ONNX 转换 → ORT/RapidOCR 适配。检查 exporter/框架/转换器版本、opset、算子、动态宽高/batch、输入布局、归一化、输出语义、字典顺序、特殊类别和外部数据文件；不是只改扩展名。
3. **看哪里**：T8 的 export inference model、dictionary 与部署，T9 的支持矩阵/opset/动态形状，T5 的 EP/模型运行与性能。若目标训练版本暂无可靠 ONNX 导出或 RapidOCR 适配，不保证必然转换成功，应冻结候选并另行评估部署方案。
4. **工时分配**：导出/转换与兼容检查 6–10 小时，转换前后及 CPU 全链回归 6–10 小时，制品/回滚整理 4 小时，共 16–24 小时。复杂算子适配和自定义转换研发超出预算。
5. **当前项目练习**：未来先用同一规范化输入比较原框架与导出模型的张量（预先定义数值容差），再比较解码文字与框，最后验证字段、关键整串、拒绝率和 CPU 性能。训练用 GPU 不代表部署要用 GPU；目标 CPU 不支持的精度/算子必须暴露为失败。新模型、字典与配置另存候选包，不覆盖旧包。
6. **输出/验收**：制品清单含模型/字典/配置 hash、版本、来源、许可、输入/输出约定、转换工具及评测记录；转换前后差异和 CPU 冷启动/稳态性能报告、回退步骤。冻结候选后执行最终独立测试；能计算但字符映射错、关键数值退化、时延超限或许可未清楚，都不能发布。CPU 回归不等于已实现 Java/HTTP 服务。
7. **条件/误区**：最终 CPU 机器是必需验收环境，导出/原框架对照可能还需原训练环境。不要把普通格式转换叫量化，不认为同名文件等于同权重，不把允许浮点容差解释成允许数字事实错误。

## 11. 学完之后如何持续提升

1. 每次只选一个主要瓶颈，形成“错误证据 → 假设 → 一个主要变量 → 固定评测 → 保留/回退”的闭环。复盘同时写未改善项，不只展示成功例子。
2. 实验摘要只记录非敏感指标、版本、hash 与错误类型。真实图片、文字、裁剪和标签留在受控环境，公开文档不复制生产值。缺少真实数据权限时用合成练习，但明确不能据此推断业务准确率。
3. D 后优先补服务工程：模型生命周期、线程安全、有界并发、超时、安全、Java 契约、离线制品与回滚；这些另立项目任务及工期，参考[需求](../requirements.md)和[开发规范](../PYTHON_DEVELOPMENT_STANDARDS.md)。
4. F/G 后再按证据选扩展课题：数据主动采样、蒸馏、量化、版面关系、算法论文。每个扩展先写收益假设与成本上限，不将可选研究塞进首次微调主线。
5. 个人能力验收：能解释为什么改、如何复现、在哪些子集变差、何时拒绝结果、怎样回滚，比“跑过几个库”更重要。本文不给精度、显存、样本量和生产工期保证。
