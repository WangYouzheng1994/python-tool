## 17. Java 类比、术语速查与常见误区

### 17.1 只类比职责，不硬套产品

| 熟悉的 Java 工程概念 | 可以帮助理解的职责 | 类比失效处 |
| --- | --- | --- |
| 构建/发布流程 | 离线生成可部署制品 | 训练不是确定性编译，而是数据驱动的数值优化 |
| 配置与资源文件 | 模型配套字典、前后处理约定 | 修改资源可能破坏输出类别语义，不能任意替换 |
| 运行环境 | ORT 执行模型计算 | ONNX 不是 Java 字节码，模型不是 JAR |
| 任务 SDK | RapidOCR 封装 OCR 流程 | 它不是 JRE，也不等于底层执行引擎 |
| 依赖锁定 | `uv.lock` 管理 Python 依赖 | 不包含模型资源及完整训练复现环境 |
| DTO/业务校验 | 字段契约、状态、证据与校验 | 格式合法不保证识别事实正确 |

PaddleOCR 与 Spring 没有严格一一对应关系；不要为了熟悉而把“训练框架、模型体系、SDK、推理引擎”都称为同一个框架。

### 17.3 常见误区清单

1. “OCR 与深度学习是二选一”——任务与方法不是同一层。
2. “把像素变成数字就是模型量化”——编码与低精度量化不同。
3. “识别一次权重就学一点”——正常推理计算激活，不更新参数。
4. “训练是随机乱试，最终保证最优”——梯度指导优化，但没有一般性全局最优和完美识别保证。
5. “数据、学习率、显卡一样必定得到同样文件”——随机性、状态和非确定性还需控制。
6. “微调就是从头造框架”——可使用现有框架和预训练成果。
7. “Paddle 是 PyTorch 的壳，独立框架又必须每行原创”——两种说法都错。
8. “PaddleOCR、PP-OCR、RapidOCR、ORT 是同一个模型”——项目体系、系列、SDK 和运行时不同。
9. “ONNX 是训练框架，所有 ONNX 任意后端通吃”——格式与执行能力、兼容范围不同。
10. “同 hash ONNX 就有相同 OCR”——还要对齐输入、字典、runtime、前后处理和字段规则。
11. “装 GPU 包必然比 CPU 快”——EP、依赖和实际端到端负载决定结果。
12. “ModelScope/Hugging Face 就是训练方”——平台、发布、转换与训练角色要拆开。
13. “高分和格式合法证明数字正确”——需要独立验收及受控人工复核。
14. “真实样本跑通、合成用例通过等于生产准确率通过”——验证对象和数据范围不同。
15. “上下文、KV cache、RAG 都是在微调”——它们本身不更新参数。
16. “不把模型放 Git 就不用管理版本”——运行资源同样需要来源、hash、许可和回滚。

### 18.2 建议的学习与实践顺序

1. **先理解分层**：读[第 1 节](1-行业与机器学习基础.md#sec-1)、[第 2 节](1-行业与机器学习基础.md#sec-2)、[第 8 节](4-OCR体系与模型制品.md#sec-8)、[第 9 节](4-OCR体系与模型制品.md#sec-9)、[第 10 节](4-OCR体系与模型制品.md#sec-10)、[第 11 节](5-推理运行时与性能精度.md#sec-11)，能口述“训练框架 → 模型制品 → runtime → OCR 流水线 → 字段”。
2. **再理解训练**：读[第 3 节](2-训练原理与数据集.md#sec-3)、[第 4 节](2-训练原理与数据集.md#sec-4)、[第 5 节](2-训练原理与数据集.md#sec-5)、[第 6 节](3-训练框架与模型微调.md#sec-6)、[第 7 节](3-训练框架与模型微调.md#sec-7)，补齐线性代数中的矩阵/张量、导数与链式法则、概率统计和优化基础，不必一开始推导全部论文。
3. **先做可复现推理**：记录模型/字典 hash、环境、配置和计时边界；只用合成或经授权样本，按阶段观察错误。
4. **建立业务评估**：定义数字整串及字段指标、拒绝率和代表性回归集；在明确数据访问授权后对照原图，不以自动解析通过替代事实核验。
5. **再比较方案**：只改变一个主要变量，比较配置、预训练模型与目标设备，不根据品牌、地域或单次速度拍板。
6. **有数据证据再微调**：按[第 6 节](3-训练框架与模型微调.md#sec-6)执行，从已维护的训练方案开始；若需安装框架、下载资源或外部服务，另行说明目的和影响并取得相应授权。
7. **最后服务化**：确认需求、Java 契约、安全、并发、生命周期、离线交付和回滚；学习结论不自动变成生产选型。

## 19. 官方参考与核验边界

1. [PyTorch](https://pytorch.org/docs/stable/index.html)：张量、自动求导与训练开发参考。
2. [TensorFlow](https://www.tensorflow.org/guide)：建模训练与生态参考。
3. [PaddlePaddle/Paddle](https://github.com/PaddlePaddle/Paddle)：独立深度学习框架。
4. [PaddlePaddle/PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)：OCR 训练、评估、模型及部署工具。
5. [PaddlePaddle/Paddle2ONNX](https://github.com/PaddlePaddle/Paddle2ONNX)：Paddle 模型到 ONNX 转换。
6. [RapidAI/RapidOCR](https://github.com/RapidAI/RapidOCR)：OCR 推理流水线、模型适配及后端说明。
7. [onnx/onnx](https://github.com/onnx/onnx)：交换格式与算子规范。

9. [Hugging Face 模型文档](https://huggingface.co/docs/transformers/index)：不同模型类型的接口与任务参考；不是当前模型镜像证明。
10. [ModelScope RapidAI/RapidOCR](https://www.modelscope.cn/models/RapidAI/RapidOCR)：现有本地配置和历史记录指向的发布渠道；不是原始训练方证明。
11. 以上为官方项目/组织参考入口，本轮未联网核验可达性、最新 API、许可证或兼容矩阵。正式训练、转换、升级或商用前，按具体版本重新核查并实测；当前没有核实框架采用率百分比或完整模型来源链。
